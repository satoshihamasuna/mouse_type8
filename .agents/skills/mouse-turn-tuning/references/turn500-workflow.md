# turn_500の調整方針

2026-11-10に整理した方針。既存GUIを使い、制御の追従確認→単体の軌道調整→再現性確認→連続走行の順に進める。
停止位置に加え、旋回中の通過位置と出口の進行方向を合わせる。方針の保存自体は、新しい走行・書込みの依頼を意味しない。

## 1. 条件と目標をそろえる

- 対象機体、実機の`preset:500`と`velo:0.5`、吸引、前走加速度、壁制御モード・壁切れ方式を記録する。左右は別々に評価する。
- 電圧、開始位置・向き、走行面、カメラ配置・高さを記録する。条件が変わった場合は比較可能かを確認する。
- ターンごとに目標終点・出口方向・通過位置を決める。今回のlong180の横移動目標は90 mm。ほかのターンへそのまま流用しない。
- 合格条件は平均ずれ、各試行の最大ずれ、ばらつき、出口方向で判断する。許容誤差は盤面の幾何と測定精度に合わせて記録する。

## 2. 基準の動画とCSVで制御追従を確認する

- 現在のプリセットまたは保存済み候補を基準に、速度・角速度の目標と実測を比較する。ログの実際の時刻列・周期を使う。
- 追従遅れ・振動・出力飽和などが軌道を左右している場合はPID/FFを先に見直す。追従が安定していれば幾何調整中は維持する。
- 動画の認識不足、走行区間の録画外、CSV欠落、設定不明の記録は位置評価の集計から除外し、元資料と理由を保存する。
- Pixel調整GUIの全フレーム検査は、走行区間と前後の観測を含めて確認する。速報だけで採用しない。現行の観測率等の条件は[Pixel README](../../../../tools/pixel_camera_README.md)を参照する。

## 3. 単体・回数1で軌道を合わせる

探索中は原則1項目ずつ変えて比較し、変更前後の実機設定を保存する。目安の順序は以下とし、観測した原因に合わせて戻って確認する。

| 項目 | 主に見るもの |
| --- | --- |
| 半径`r_min` | 横移動量、旋回中の通過位置 |
| 旋回角・角度補正 | 出口から直進する方向、ログの旋回角 |
| `Lstart` | 旋回に入り始める位置、旋回軌跡の前方頂点 |
| `Lend` | 旋回後の出口位置 |

これらは互いに影響する。半径や角度を変更した後は、入口・出口も再確認する。
long180は始終方向が平行なので、終点だけから`Lstart`と`Lend`を一意に分離できない。入口位置や軌道の頂点など、盤面の幾何に基づく追加条件を使う。

現在の非ゼロ設定を比較する方法と、`Lstart=Lend=0`を前提とする専用解析ツールの逆算を区別する。
後者を使うときだけ[長さの逆算手順](../../mouse-log-analysis/references/turn-lengths.md)の入力条件を満たす。既存の有効な比較撮影を一律にゼロ設定で取り直さない。

## 4. 同じ候補の再現性を確認する

- 候補が見えたら、同じ条件の有効な単体撮影を原則3本そろえる。条件と設定が対応する既存の有効データは再利用する。
- 平均・中央値に加え、各試行の最大ずれと観測範囲を併記する。平均がゼロに近いだけで完了としない。
- ばらつきや測定の不確かさより細かい変更は、効果を確認できるかを先に判断する。繰り返しが散る場合は、開始姿勢・電圧・計測・制御追従のどこが原因かを調べる。
- 盤面上の絶対位置、機体軸中心、目印の高さ、同期精度の検証状況を区別する。相対目印軌跡の成立を絶対精度の保証として扱わない。

## 5. 試験用Paramsと連続走行へつなぐ

単体GUIのRAM設定は、現在のturnpatternや最短走行へ自動反映されない。
候補・入力資料・実機のPID/FFを保存したうえで、依頼された範囲で対象機体の試験用Paramsへ反映し、ビルド・書込み後の値を確認する。
短い組合せから直進／斜めの接続、壁のある経路へ進める。単体候補・連続検証済み・正式採用を区別し、結果に応じて戻って調整する。

対象順序の目安は、現在の左右180→左右90→45度の入口・出口（左右）→V90（左右）→135度の入口・出口（左右）の計14パターン。
再開時は保存済みの進捗とユーザー指定を優先し、最初から全てやり直さない。`plain500`の直線速度は500 mm/s固定とは限らないため、最短経路での接続条件も確認する。

## 撮影・保存の運用

- 接続・操作は[既存GUIの手順](gui-workflow.md)と[Pixel README](../../../../tools/pixel_camera_README.md)に従う。カメラ8765と併用するときは、BLE中継・BLE GUIの両方を`--port 8766`へ合わせる。
- 録画受付だけで走行を始めない。`RECORDING_READY`に加え、録画ID・所有者・`RECORDING`状態・残り時間等を照合してから1回だけ実行する。実行指令は自動再送しない。
- 手かざしなし実行は、録画中に確認する撮影専用の一回許可に限定する。通常の実行経路へ広げない。
- 現在のPCでは`D:/TYPE8_Camera/trials/<録画ID>/`に、対応する`video.mp4`、`motion.csv`、`motion.settings.json`、撮影記録、解析結果を1撮影1フォルダーで保存する。保存先設定を変えた場合はその場所を使う。
- 元資料、入力ハッシュ、除外理由を保持する。保存済み資料の整理には`tools/pixel_camera_archive.py`を使い、機器への接続は行わない。
