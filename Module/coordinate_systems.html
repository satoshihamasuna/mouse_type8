FIRMWARE ARCHITECTURE NOTE · 2026-11-18

走行をつなぐ座標系

全体位置を保ちながら、直進・ターン・斜めをそれぞれのローカル軸で扱う。
位置の管理は Vehicle::pose に集め、参照する座標系を変えて使います。

position : mmangle : radyaw : 左旋回が正1 Vehicle → 1 pose

01 / OWNERSHIP保持する位置はひとつ。見方はふたつ。

vehicle.h の Vehicle が座標の状態を所有します。ego は実測・制御用の区間状態、ideal は目標状態、pose は全体位置と座標変換の担当です。

WORLD · 保存する状態

全体座標

world = (X, Y, θ)
走行全体の位置と機体の向き。動作切替で消さず、停止・エラー後にも残します。

LOCAL · 参照時に算出

動作ローカル座標

local = (s, e, ψ)
その動作の開始点から、前方 +s・左 +e を見る座標。位置を別に積分しません。

ORIGIN · 変換の基準

原点と軸方向

origin = (Oₓ, Oᵧ, φ)
ローカル原点の全体位置と、ローカル +s 軸の向き。機体の現在姿勢とは別の基準です。

既定の全体軸は、開始方向が +X、左が +Y。開始位置は (0, 0)、開始姿勢は 0 rad です。迷路の座標で扱う場合は、実際の開始位置・向きを pose reset X Y yaw_deg で指定します。

コード中の項目意味扱い
p.world.x_mm / y_mm全体の X / Y固定した全体軸での位置。
p.local.x_mm / y_mmローカルの s / ex が前、y が左。全体位置と原点から算出。
p.originローカル → 全体の変換動作中は固定。新しい動作・phase で更新。
ego.length / x_point / radian既存制御・検出用の区間値独自の原点・リセットがあるため、p.local と同一視しない。

実装：Inc/vehicle.h、Inc/pose_frames.h

02 / TRANSFORM原点を移し、軸を回す。

ローカル軸の向き φ だけ位置ベクトルを回転し、原点を加えると全体位置になります。逆変換では原点を引き、−φ だけ回します。

ローカル → 全体　compose(origin, local)
X = Oₓ + cos φ · s − sin φ · e Y = Oᵧ + sin φ · s + cos φ · e θ = wrap(φ + ψ)
全体 → ローカル　relative(origin, world)
s = cos φ · (X − Oₓ) + sin φ · (Y − Oᵧ) e = −sin φ · (X − Oₓ) + cos φ · (Y − Oᵧ) ψ = wrap(θ − φ)

wrap(a) = atan2(sin a, cos a)。角度は ±π の範囲へ正規化します。入力 UI の角度は度表示、計算と API は rad です。

03 / ANGLES経路方向・機体姿勢・滑り角を分ける。

角度定義主な参照先
経路方向 φローカル前方軸の全体での向き。論理ターン角で次の方向を決める。origin.yaw_rad、reference_yaw_rad
機体姿勢 θ現在の機体の向き。測定した旋回量と採用した推定で更新。world.yaw_rad
姿勢偏差 ψその動作の軸からの機体の向きの差。wrap(θ − φ)。local.yaw_rad
滑り角 β機体の向きと速度方向の差。速度方向は θ + β。ego.turn_slip_theta、ideal.turn_slip_theta

reference_yaw_rad は次の経路軸にも使う方向です。旋回中は origin.yaw_rad が入口の軸を保ち、旋回完了時に complete_turn() が経路方向を更新し、続く set_phase() が新しい軸を取り込みます。

右90°に補正 +1.5°を加えた例

論理角は −90°、実際の旋回が −88.5°なら、出口の姿勢偏差は +1.5°。complete_turn(-π/2) は経路方向だけを変え、機体の姿勢を論理角へ丸めません。

滑り角は姿勢の重複ではない

機体が同じ方向を向いていても、横滑りがあれば速度の向きは変わります。βは滑りモデルに必要な状態です。未使用の保存変数 turn_slip_dot は削除済みです。

各EKFの姿勢原点と、旧制御値 ego.radian の原点も区別します。ego.radian は区間や補正処理でゼロ化されるため、全体の θ を表す値として読み替えません。壁制御内部の Zirconia には右正・m単位の偏差があり、IRタスクで左正・mmとの符号・単位変換を行います。

滑り係数 K は吸引I/Oから代入せず、Vehicle::turn_slip_k_m_s2() で実測・目標の計算に共通の基本値を参照します。機体Aは以前の推定値（非吸引41.28055、吸引254.90725 m/s²）、未校正Bは従来値（75 / 250 m/s²）です。直前のファン出力が0か正かで切り替え、係数の保存変数は持ちません。EKFの適用条件は別に確認します。

実装：turn_motion.cpp、turn_pose_param.h、search_turn_heading.h、ir_sens_task.cpp

全体・ローカル・原点の参照。

入力・推定全体座標への反映実装の入口
通常の移動predict_body()。前後・左右増分を中間姿勢で回転。現在の呼出しはエンコーダ前後移動量、左右増分0、ジャイロ×0.001 s。Interrupt::preprocess()
採用中のターンEKFpredict_turn()。EKFが積分済みの固定軸増分を全体へ回転し、姿勢増分も1回だけ反映。通常予測との選択で使用。TurnPose::Output
直進の側壁推定固定した通路原点へ現在位置を変換し、採用した横位置・姿勢を置き換えて全体へ戻す。進行位置は保持。SetWallControl_RadVelo()
適用した縦位置補正correct_passage()。実際に適用した量だけ、経路方向へ反映。ObserveFeature()、ApplyWallPositionCorrection()
斜め柱EKF開始時に固有の進行位置・横位置を全体へ結び付け、校正・品質条件を満たす採用状態を adopt_world() で反映。BeginDiagonalPoseRoute() / RecordPillarCandidates()

Tracker は座標変換と採用結果の反映を担当します。各EKFの内部状態と共分散は、その推定器が保持します。全体側で同じセンサを独立観測として再融合する処理はありません。

共分散の固定軸変換は P′ = J P Jᵀ（J = diag(R(φ), 1)）で、rotate_covariance() を用意しています。位置の単位はmmなので、交差項の単位はmm·radです。この関数は推定原点そのものの不確かさを追加しません。全体の新しいEKFや全体共分散は実装していません。

機体A/Bで座標の規約は共通ですが、EKFの校正・採用範囲は機体ごとです。BにAの校正を適用する仕組みではありません。ターンEKFが不採用なら通常の予測経路を使います。

05 / LIFECYCLE境目では原点を変え、全体位置を残す。

01 · START走行開始

pose.start()
設定済み開始座標を採用。カウンターと有効性を初期化。

02 · STRAIGHT直進の原点

新しいモーションを予約し、set_phase() で原点と軸を取得。

03 · TURN入口軸のまま旋回

原点を入口に置き、軸は固定。実際の機体姿勢を更新。

04 · NEXT出口から次の動作

論理角で経路方向を更新。新しい原点からローカル位置を算出。

操作全体・動作ローカルへの作用補足
set_start(p)停止中に開始座標を設定し、現在の座標もそこへ戻す。実行中は拒否。シェルは制御有効・実行状態も確認。
new_motion()モーション番号を増やし、次のフレーム更新を予約。この呼出し自体では位置原点を動かさない。
set_phase(phase)phase変更または予約があれば、現在の全体位置と経路方向を新原点にする。同じphaseの繰返しでは維持。位置はローカル0、姿勢偏差は保持。
complete_turn(logical)経路方向とフレーム更新予約を変更。全体位置・機体姿勢は保持。論理角を使う。角度補正値は加えない。
ego_initialize()
ego_integral_init()		旧egoの区間値とログ用原点を初期化。全体位置・動作原点は保持。local も同じ値を保つ。ideal の初期化はposeを変更しない。
Motion_end()
エラー停止		pose.stop() で追跡を止め、最後の全体位置と動作ローカルを保持。後続の旧ego初期化でログ用原点は変更。次の走行開始時に開始座標へ戻る。

motion はモーション番号、frame は原点・軸の更新番号です。ひとつのターン指令でも、前直進・旋回・後直進で複数のフレームを持てます。次モーションの設定待ちでは同じ軸を使い続けます。

実装：Motionの状態setter、Motion_start() / Motion_end()、ターン完了処理

06 / TELEMETRY旧ログの原点は、動作原点とは別。

旧 ego.turn_x/y の保存変数と独立積分は削除済みです。互換性のためログの列名を残し、pose.log_position() で全体位置をログ用の固定原点へ変換します。持つのは参照原点だけで、別の位置推定ではありません。

参照・列名位置の意味軸の対応
pose.snapshot().local現在の動作・phaseの原点から見た位置。x_mm = 前方s、y_mm = 左e
pose.log_position()従来のゼロ化箇所で設定するログ用原点から見た位置。x_mm = 前、y_mm = 左
ego.turn_x 列ログ用原点に対する左位置 [mm]。log_position().y_mm
ego.turn_y 列ログ用原点に対する前位置 [mm]。log_position().x_mm
ideal.turn_x/y 列更新処理がなかった旧理想位置の互換列。予約値 0 を出力。

ログの x は左、Poseのローカル x は前。列名が似ていても成分の対応は逆です。また、ログ用原点は origin と独立なので、ego.turn_x/y を snapshot().local と直接比較しません。

reset_turn_position_for_log() はログ用原点の位置を現在の全体位置に置き、軸角を wrap(world.yaw_rad − ego.radian) にします。これは旧センサ姿勢の原点を考慮した変換です。全体位置・動作ローカル・予測回数は変更しません。

列名・順序・単位・保存/配信バイナリ形式は従来どおりです。値の生成元は単一のposeへ移り、エンコーダと採用したEKF・壁補正を反映します。過去の速度による独立積分とは数値が変わる場合があります。

全体位置と現在の動作ローカル全項目を周期CSVに追加したわけではありません。これらの参照先は pose show とsnapshot APIです。

実装：reset_turn_position_for_log()、reset_log_origin() / log_position()、LogData::logging()

07 / ACCESS同じ時点の座標をまとめて読む。

C++

// Vehicle が所有する状態を一度に取得。
const auto p = vehicle->pose.snapshot();

// 全体位置・姿勢
p.world.x_mm;
p.world.y_mm;
p.world.yaw_rad;

// 動作ローカル位置・姿勢偏差
p.local.x_mm;   // s: 前
p.local.y_mm;   // e: 左
p.local.yaw_rad;

// ローカル → 全体の変換原点
p.origin;

snapshotはIRQマスクを保護しながら状態をコピーし、ローカルを算出します。別々に取得して時点を混ぜず、一つのsnapshotを使います。

シェル

pose show

# 開始座標を (0, 0, 0) に設定
pose reset

# 実際の開始位置が (45,45) mm、北向き
pose reset 45 45 90

reset の入力角だけは度です。表示・内部値はrad。指定した開始座標は次の Motion_start() にも使用し、Flashには保存しません。

phase番号：0=NOP、1=直進、2=斜め、3=旋回、4=その場旋回、5=制動。停止後は最後に追跡したphaseの座標が残ります。

診断項目読み方
active / valid追跡中か、増分の拒否履歴がないか。valid は絶対位置精度の判定ではない。
samples受理した予測増分の回数。通常予測とターン予測は同じ周期で重ねない。
corrections補正・採用座標を反映した回数。独立した観測の件数ではない。
rejected非有限値などの拒否回数。予測増分は移動長20 mm以下・旋回量1 rad以下を確認。

異常値を拒否した場合は有限な位置を保ち、valid:0 を次の開始・原点再設定まで保持します。実機の位置精度と追加処理のIRQ時間は未評価です。
