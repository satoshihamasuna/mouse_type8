# 機体B・探索370 mm/sの単体採用候補

2026-11-21、機体Bの左右370 mm/sを動画と実機設定付きログで調整した。左右それぞれ同じ候補3本で、実測入口相対のマーカー中点の終端誤差が各軸2 mm以内、出口進行方向の誤差が1.5度以内だったため、Bの370専用定義へ反映した。

| 方向 | 半径 mm | Lstart mm | Lend mm | 論理角 deg | 補正 deg |
| --- | ---: | ---: | ---: | ---: | ---: |
| 右 | −26 | 8.60 | 10.40 | −90 | −1.0 |
| 左 | +26 | 7.30 | 11.50 | +90 | 0.0 |

速度PIDは左右ともKp/Ki/Kd = 5.0 / 0.02 / 0、角速度PIDはBの0.1 / 0.0015 / 0。旋回加速FFは0.000690 V/(rad/s²)、減速FFは0.000555 V/(rad/s²)。他のFF項はBの`ff_gain_default`と同じで、jerkと旋回中の並進補償は0。方向ごとにFFオブジェクトを持つが、今回の値は同一。

単体GUIでの明示PIDと通常のパラメータ呼出しを揃えるため、370の`t_param.search_straight_sp_gain` / `search_straight_om_gain`にも同じPIDを指定した。GUIの明示指定は引き続き優先する。B350は320から速度だけを変えた未調整の初期値を保持し、280/300/320・通常探索の既定320 mm/sは変更していない。Aの測定係数は使用していない。

## 条件と採用範囲

対象は機体B、370 mm/s、吸引OFF（保存duty 650）、回数1。外部の前走/後走は各45 mm、前走加速度・後走加減速度は6.5 m/s²。`wall_ekf:shadow`、`wall_edge:legacy`、`turn_ekf:control`を実機応答で記録したが、Bの探索ターンEKFは未校正で適用対象外。前マーカーは緑、後ろは赤、カメラ高さは概略1500 mm、前/後マーカー高さ10/1 mm。露出補正−1.5、zoom 1.8、torch OFF、focus lock ON。

操作者の「配置は概略でよいので、入口相対の調整を進めてほしい」に従い、実測した入口直線を座標軸に使う。ターン開始点から右/左45 mm・前45 mmをLendの目標とし、外部前走の誤差や後走停止時の惰走をターン長へ混ぜていない。高さ補正した前後マーカーの相対中点であり、絶対車軸位置・高さ補正済みの機体yawではない。

保存1 msログと時刻付きストリームの実サンプル一致から、実周期約1.016 msを求めて幾何評価へ使った。時計の原点は入口の生エンコーダ距離だけで照合し、旋回・出口・縮尺を当てはめていない。独立したハードウェア同期・実測尺度の校正ではない。

反復前に決めた暫定基準は[記録した採用計画](selected_trials.json)に含む。走行の生観測率95%以上、評価フレームごとの登録ArUco 2個以上、入口時計RMS 1.5 mm以下・前半/後半差2 ms以下、入口/出口直線のRMS 0.75 mm以下・範囲30 mm以上、停止散布RMS 1 mm以下、欠落/CRCエラー/接触なしを維持した。全フレームの既存自動停止チェックも確認した。

## 制御値を選んだ根拠

右の同条件比較で速度Pを1.2 → 3.0 → 5.0とし、旋回中の速度RMS誤差は19.89 → 15.87 → 11.87 mm/sへ減少した。P5で旋回加減速FFを既定値から25%・50%更新した比較では角速度RMS誤差が1.23 → 0.99 → 0.71 rad/sへ減少した。RMS区間は目標角速度の絶対値が最大値の2%を超える範囲。公称1 msでの制御ログ比較と、実測周期を使う幾何評価を区別する。

Bの基準/P3ログから得た閉ループ近似は角加速0.001001672、減速0.000731689、条件数7.78・R² 0.953。独立したモータ同定ではないため、既定の約0.000378から半量だけ更新し、0.000690 / 0.000555に丸めた。角速度比例・バイアス項は励起が不足し、並進FF推定も条件数44.9と負の切片のため採用していない。左ではこの制御候補を独立に走行確認し、左自身の動画で前後長と角度補正を決めた。左の最終3本の速度RMS誤差は8.48～10.68 mm/s、角速度RMS誤差は0.65～0.68 rad/s、欠番・電圧飽和なし。

## 入力と未採用記録の保持

原資料は`tools/logs/pixel_camera/search370_B_20261121_v1/`。右採用は`right_geometry02`と`right_geometry02_repeat01/02`の008～010、左採用は`left_geometry01`と`left_geometry01_repeat01/02`の012～014。各フォルダの`local_execution/run_<request_id>/`に動画参照、実機設定、`saved_1ms.csv`、`telemetry.csv`、全フレーム結果、入口時計と幾何の監査を保持した。各撮影の一式保存は`D:/TYPE8_Camera/trials/<recording_id>/`、後から追加した幾何監査と再解析は元フォルダに保持している。

初回要求001はBLE接続前の準備で失敗し、実行指令は未送信。実際の走行は002～014の13回で、各回の現在の配置・両方ON・手離しを操作者が確認してから1回のみ送信し、全回接触なし・両方OFFの返答を記録した。実行指令の再送は0回。

右003は入口時計の前半/後半差2.211 msで不合格として保持。左011/012の間引き速報は静止観測数不足で失敗し、同じ範囲の全フレームで確認した。左012の最初の全フレーム解析では、ブレーキ後の既存停止窓の末尾が解析範囲で切れ、自動停止判定が不合格だった。元の`full/`を残し、範囲を`decision_camera_seconds + 0.75 s`まで広げた`full_postroll/`を同じCLI・条件で再解析し、停止窓0.396 s・散布RMS 0.141 mmで合格した。013/014は初めからこの広い範囲を使った。検出値の補間採用・品質閾値の緩和は行っていない。

左のキャッシュ照合許容差は、盤面360 mmにおけるfloat32の2 ULP（0.000061 mm）。数値の往復変換誤差だけの許容で、物理計測の品質条件とは別。元の厳しすぎる照合で失敗した記録も保持した。
