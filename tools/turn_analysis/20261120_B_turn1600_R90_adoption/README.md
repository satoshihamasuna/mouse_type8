対象は[turn_1600.cpp](../../../Params/Param_B/turn_1600/turn_1600.cpp)。旧定義はコメントで残した。変更した有効な形状定義は左右90度の2つで、Bの既存PID・FF、他のターン定義、Aの設定は今回変更していない。

`degree_correction`は論理角へ加算するため、物理モーション生成角は右−89度、左＋89度となる。論理角±90度と左右の列挙値は保つ。`param_R90_1600` / `param_L90_1600`を参照する`mode_1600`と可変速度用の一覧は同じ定義を使う。

## 右90度の測定条件と根拠

機体B・1600 mm/s・吸引ON/duty650・前走加速度6.5 m/s²。前の緑・後ろの赤のマーカーを使用し、カメラ高さは概算1500 mm、調整盤は360 mm / 45 mm格子。各動画の入口直線を基準にした相対マーカー中点の評価であり、厳密な初期位置・角度合わせは要求しない。

## 検証と未確認事項

機体Bの`Debug-MouseB`をConfigureしてビルド成功。起動ラッパー`cube-cmake`がこの環境で使用できないため、同じSTM32Cube導入済みCMake 4.3.1+st.1、Ninja 1.13.2+st.1、Arm GCC 14.3.1+st.2を直接使用した。変更はB専用の定数であり、最適化・共通ファームウェア・ビルド設定の変更はない。

パラメータ参照は`python -m unittest discover -s tools/tests -p test_run_param_linkage.py -v`でA/Bの実体共有を確認し、1テストPASS・スキップ0。生成ELFから左右90度の構造体を読み出し、速度・半径・Lstart/Lend・論理角・補正を保存済み候補と照合して一致を確認した。結果とELFのハッシュは上記の反映記録へ保存した。

検証中に同じファイルへ別作業の左右180度の変更が入ったため、それを保持して最新のソースで再ビルドした。今回の左右90度の変更と同時作業の差分は反映記録で区別している。

更新ファームウェアの実機書き込み、書き込み後の走行、左90度の実測、盤面固定の絶対車軸精度、連続・最短への接続は今回確認していない。機体B用のターンEKF独立同定も未実施で、Aの同定値は流用していない。
