# 機体B turn1600 左V90への鏡映反映

2026-11-21、ユーザーの「ひだりもはんえいして」に従い、Bの右V90暫定値を左へ鏡映した。**左の実走は未確認**。右の出口角度も目標未達であり、左右の調整完了とは扱わない。

| 項目 | 左V90の反映値 |
| --- | ---: |
| 速度 / 半径 | 1.6 m/s / 左40 mm |
| Lstart / Lend | 6.0 / 17.4 mm |
| 論理角 / 角度補正 | +90 / +1.20° |
| 物理指令角 | 左91.20° |

FF係数は左右で同じ値とし、左専用の`ff_gain_turnLV90_1600`を`param_LV90_1600`から参照する。半径・論理角・角度補正の符号を右と反転した。変更前の左テーブルはソース内のコメントに保持した。

根拠は[右V90の測定記録](../20261121_B_turn1600_RV90_adoption/README.md)と、今回の明示的な鏡映指示。右の1本では入口相対のLend位置誤差0.323 mm、出口92.031°であり、左へ適用して同じ精度が出ることを示す測定ではない。左の単体・連続・最短での実機評価、BのEKF同定は未実施。

[evidence.json](evidence.json)に反映値・指示・前後ハッシュ、[source_patch.diff](source_patch.diff)に今回の差分を保存する。既存の測定・アーカイブは変更しない。実機接続・走行・Flash書込みは行わない。

`Debug-MouseB` Configure/Buildが成功し、既存のA/Bパラメータリンク検証1件も成功（スキップ0）。左右V90のFF・テーブル・参照パラメータがELFに含まれることと、右の定義が不変であることを確認した。[validation.json](validation.json)に結果を保存した。`cube-cmake`の環境解決が使えないため、前回と同じSTM32バンドルのnative CMake / Ninja / Arm GCCで同じプリセットを使用する。
