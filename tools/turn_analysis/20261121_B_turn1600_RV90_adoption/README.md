## 実測の結果

同じ最終設定の適格実走は1本。B用HY0020は`E1:7F:86:21:84:73`、前緑/後赤、カメラ高さは概ね1,500 mm。ユーザー指定の概略配置(315,90) mm付近・左下135°から、干渉なし・両方ON・手離しを確認して実行した。

| Lend残差（入口に対する右/前） | +0.322 / +0.015 mm |
| Lend位置誤差 | **0.323 mm：目標3 mm内** |
| 旋回中の追従RMS | 4.162 rad/s |

各評価フレームの実ArUco登録、入口/出口直線、入口車輪距離による時計照合、固定した後半静止窓の品質を通過。元summaryも全telemetryと動画による停止確認を通過した。[動画幾何レビュー](midpoint_review.json)、[角速度追従レビュー](tracking_review.json)、[根拠と入力ハッシュ](evidence.json)を参照。

補正0°で87.672°、−2°で91.683°の2点から−1.20°を試したが、実測92.031°は補間予測90.078°と一致しなかった。位置が合った実走済み候補として暫定反映し、角度補正の単調な応答や再現性を確認できたとは扱わない。

## 採用範囲と未確認事項

- 測定点は高さ補正した前後マーカー中点。実測入口に合わせた相対評価であり、盤面固定の開始/出口/停止目標、車軸や機体yawの校正を保証しない。
- 機体BのEKF係数は未校正。今回の動画から未同定の係数を既定値で補っていない。
- 旋回直後の振れが残る。保存ログはLendまでで、停止と後走は連続CSV・動画で別に確認する。
- 初期のB値からの変更履歴と全試行は`tools/logs/pixel_camera/turn1600_B_rv90_20261120_v1/`に保存。BLE切断の不完全ログと走行前失敗を適格本数へ含めない。
- 切断後はスマホBLEアプリの終了を確認し、連続配信を5→10 msへ下げた。制御/保存ログは1 msのまま。今回の成功だけで切断原因の解決とは断定しない。
- 従来の光学品質条件を維持。ユーザー指定により追加の3 mm/1°設置条件は使用しない。
- ファームウェアのFlash書込みは行っていない。

## ソフトウェア検証

反映後の`Debug-MouseB` Configure/Buildと、A/B実パラメータの共有リンク検証1件が成功（スキップ0）。Buildは`ninja: no work to do`で、ELF内の右V90テーブル・専用FF値・参照先も照合した。結果は[validation.json](validation.json)に記録した。実機へのFlash書込みは行っていない。
このシェルでは`cube-cmake`ランチャーのCube環境解決に失敗したため、同じSTM32バンドルのCMake 4.3.1、Ninja 1.13.2、Arm GCC 14.3.1で同じ`Debug-MouseB`プリセットを使用する。
