変更前から存在した同じファイル内の90度・135度進入などの作業差分は保持した。今回の追加差分は左右45度進入の形状定義とその根拠コメントである。以下の測定は右側だけで、左単体の実機評価は未実施。

## ビルド・参照の検証

`Debug-MouseA`をConfigureしてビルド成功。`cube-cmake`がPATHにないため、既存CMakeCacheで使用されているSTM32CubeのCMake 4.3.1、Ninja 1.13.2、Arm GCC 14.3.1を同じpresetで直接使用した。変更はA専用パラメータで、共通制御・最適化・ビルド設定の変更はない。

`python -m unittest discover -s tools/tests -p test_run_param_linkage.py -v`は1テスト成功・スキップ0。A/Bそれぞれの実パラメータをホストコンパイルし、翻訳単位間の参照共有を確認した。

生成したARM ELFから左右45度の形状、方向別PID・FF、`param_inR45_1800`と`param_inL45_1800`の参照、`mode_1800`と`mode_1800_acc_v2`の左右45度要素を読み、採用値との一致を確認した。Bのソースと45度進入以外の実装が変更前と同じであること、ビルド中に対象ソースが変化していないことも照合済み。

更新ファームウェアの実機書き込みと、その後の走行は未実施。右単体の入口相対評価であり、絶対車軸位置・盤面固定の設置精度・鏡映した左45度の実走・連続／最短走行・新しいEKF係数の採用は今回の確認範囲に含めていない。
