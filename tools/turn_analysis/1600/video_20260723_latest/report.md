# 2026-07-23 最新ログ・動画照合

## 結論

今回の動画は、直近5ログと走行種別・撮影順の両方で対応している。

角速度と最終角度の追従は良好で、全ターンの角度誤差は絶対値0.68 deg以内だった。
終点誤差の主因は角度PIではなく、並進軌跡モデルと現在のLstart/Lendである。

特に重要なのは、`ego.turn_slip_theta` の beta を実際の速度偏角とみなし、
`v*sin(beta)` を横速度として位置へ100%加えるモデルが今回の動画・ログと合わないことである。
このモデルはlong R180の終点をほぼ目標どおりと予測するが、動画では出力方向へ約15--25 mmずれている。
エンコーダ＋ジャイロ積分も同じ向きへ21.2 mmのずれを示す。

betaによる位置補正を使わず、実測`ego.velo`と`ego.rad_velo`だけを再生したモデルは、
5ターンすべてでエンコーダ＋ジャイロ軌跡と1.5--5.9 mm以内で一致した。
したがって、現状のbetaは運動状態量としては有用でも、実横滑り速度角として直接使うべきではない。

## モデル構造の検証

実測速度・角速度を使った再生軌跡と、エンコーダ＋ジャイロ積分軌跡の距離差は次のとおり。

| ターン | beta横速度＋接地スリップモデル [mm] | beta位置補正なし [mm] |
| --- | ---: | ---: |
| long R90 | 16.5 | 1.5 |
| long R180 | 23.8 | 4.2 |
| in R45 | 12.2 | 5.9 |
| in R135 | 21.9 | 3.2 |
| R V90 | 20.4 | 5.9 |

この結果から、次の実装方針が妥当である。

1. 軌跡計算の基本は実測`ego.velo`と`ego.rad_velo`の積分に戻す。
2. betaは制御・状態観測には残しても、`v*sin(beta)`を位置へ直接100%加えない。
3. 横滑りを再導入する場合は、動画から独立に求めた小さい係数を掛け、long180だけで同定しない。
4. Lstart/Lendは上記の再生軌跡を基準に再計算する。

## 加速度の符号

右旋回5種では、`ego.rad_velo < 0`、`ego.horizon_accel < 0`、betaは正となった。
`horizon_accel = -read_accel_x_axis()`という現在の符号規約で、`v*omega`の向きと一致している。
今回のログからは加速度符号が逆である兆候はない。

ただし、横加速度は移動平均の遅れが大きく、短いin45やV90ではピークが旋回後半へ寄る。
そのまま二重積分して横変位を求める用途には向かない。
