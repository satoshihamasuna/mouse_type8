# 既存の青色LEDによる同期の確認

2026-11-12、機体A turn500の42試行を確認した。
**既存のLED点灯開始を動画―ログの同期基準に使える。新しい点滅機能の追加が先に必要という説明は適切ではなかった。**

現行`System/Src/myshell.cpp:1671`では、`Init_Motion_*`の後に`Indicate_LED(0x3f)`、
`execute_Motion()`の後に`Indicate_LED(0x00)`を呼ぶ。
ここでの開始はLstartを含むターン区間の入口で、角速度が立ち上がる瞬間とは異なる。
このLED処理はGit履歴上2026-07-23からあるが、取得ELFの同一性は未確認。

動画の保存済み`turn_led_blue_pixels`から、消灯背景の99パーセンタイル+3画素と5画素の大きい方を閾値にし、
5フレーム以上続く点灯の立上がりを検出した。
従来の`turn_led_active`は100画素以上という閾値と最長区間選択で点灯開始を落とす場合があるため、
今回はその二値列を使っていない。新しい動画追跡は行わず既存の青色画素数を使用した。

ログでは、前走からLstartへ入る時の`ego.length`のリセットを点灯開始の対応イベントとして扱った。
5 ms配信のリセット前後の時刻と、動画の消灯・点灯フレームの時刻で区間を挟んだ。
候補探索は既存同期で予想した入口から±80 msに限定し、42本すべてで候補が一意だった。
これはGPIOの切替時刻の直接記録ではなく、ソース上の順序とログの状態変化による対応付けである。

従来の軌跡同期からMCU側へ補正する量は、中央値**+7.05 ms**、範囲**−1.77～+12.63 ms**。
この差は各時刻区間の中点による暫定値で、同期誤差の保証値ではない。
露光時間・行ごとの読出し差、GPIO操作と状態変更の時間差は未補正。
また、他のLED表示処理による上書きがあり得るため、今回は消灯端を同期に使っていない。
