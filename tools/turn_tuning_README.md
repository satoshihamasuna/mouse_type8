# BLE単体ターン調整

既存の`myshell_debug.py`を拡張したGUIです。機体A/Bに対応し、パラメータ編集、配置後のボタン開始、本体ログの自動取得・画像表示・保存、任意のPixel録画をまとめて操作します。

```powershell
.\tools\Start_Turn_Tuning.cmd
# または依存環境のPythonから
python tools/turn_tuning.py
```

Python 3.10以上・Tk・pyserial・Bleakが必要です。ログ画像にはNumPy・pandas・Matplotlibを使用します。画像作成用Pythonは`TYPE8_ANALYSIS_PYTHON`で指定でき、未指定なら既存の解析環境、なければ起動したPythonを使います。録画なしではPixel接続、PyAV、ArUcoプロファイルは不要です。

ボタン開始と記録周期の変更には、この変更を含むSTM32ファームウェアが必要です。機体に対応する`Debug-MouseA` / `Debug-MouseB`をビルド・書き込みして使ってください。GUIは書き込みを行いません。

基本のループは「配置 → BLE接続 → 設定送信 → 録画・1回走行 → ログ確認・映像の自動解析 → 結果確認 → 次の試行」です。

1. 機体A/B、ターン名／左右、速度プリセットを選び、人が機体を配置します。方向・停止・手離しを確認してチェックを入れます。
2. 「① BLE接続」または上部の`Connect`を押します。機体別の広告名・アドレスで中継を起動します。この段階ではカメラ環境を要求せず、走行もしません。機体への初回接続では実機プリセットを自動で読み込み、次の試行では編集値を保持します。読み直す場合は`Load defaults`を使います。
3. 半径、Lstart/Lend、角度補正、前走加速度、PID、FF、吸引を編集し、「② 設定送信・照合」を押します。実機へ送って読み返し、一致を確認します。この操作では走行しません。右の半径・角度は負、左は正、回数は1です。探索ターンの吸引はOFFです。
4. 設定照合後に「③ 録画・1回走行開始」が有効になります。人が押すと、録画中を照合してから手かざしなしで1回だけ走行します。「録画する（Pixel）」で録画のON/OFF、「動画の処理」で録画のみ／映像解析を選べます。本体ログ周期は1～100 ms、既定1 msです。設定変更や再接続後は再び②で照合します。
5. 停止後は本体ログと動画を自動取得し、BLEを切断します。機体とHY0020の電源をOFFにしてください。ログ画像の作成と一式保存は自動で進みます。映像解析を選んだ場合は速報・全フレーム解析も実行します。その間も画像・結果フォルダーを開いて確認できます。
6. 保存・解析が終わったら結果を確認し、「④ 結果確認済み・次の試行」を押します。パラメータは保持し、配置確認と設定照合を解除します。置き直して①から繰り返します。自動の再走行・実行再送・パラメータ採用は行いません。

**映像解析を省くには**「録画する（Pixel）」をONにし、「動画の処理」を「録画のみ（解析なし）」へ変更します。③で1回走行した後、動画・本体CSV・ログ画像・設定を保存して④へ進めます。盤面参照JSON・目印設定・機体位置の解析環境は不要です。カメラ接続、撮影条件の照合、停止後の余白、動画の転送・復号・整合確認は行います。結果欄は「録画のみ（解析なし）」となり、`quick/`・`full/`の映像解析結果は作成しません。選択は次回起動にも引き継ぎます。動画は「結果フォルダーを開く」から`video.mp4`を開いて確認できます。

**盤面の傾きだけ補正するには**「動画の処理」を「AR正対補正のみ」にします。「接続・撮影条件」で盤面の登録参照JSONを選んでください。機体の色・目印・高さ・学習モデルは不要です。録画終了後、各フレームの登録済みARを2個以上使って盤面を720×720画素の正方形へ射影補正します。機体位置の推定・走行ログとの比較は行いません。参照に設定された盤面・格子品質条件は維持します。AR登録が不成立のフレームも削除せず、`AR UNAVAILABLE`を表示した黒い画面で時間を残します。前フレームの変換で補いません。

「正対補正動画を開く」で補正MP4、表示欄の「正対補正画像」で最初に補正できた画像を確認できます。結果フォルダーの`full/rectified.mp4`・`full/rectified_preview.png`・`full/rectification.csv`へ保存します。`quick/`は4フレーム間引きの速報です。補正動画の枚数とPTSは保存後に照合し、再生速度を変えません。元動画も保持します。盤面上の平面に対する補正で、機体の高さによる視差やレンズ歪みは補正しません。

初回の映像解析設定は「映像解析設定」から登録します。認識済みの盤面基準、前後の目印の異なる色、床からの目印高さ、床からレンズまでの高さを指定します。前後間隔は任意です。機体別に新しいJSONへ保存し、過去の設定を上書きしません。「ログと比較」でカメラの真下・車軸位置が未校正の場合は、前後目印の中点の相対軌跡として解析します。

解析欄は「位置だけ（盤面XY）」と「ログと比較」を選べます。簡易GUIの初回既定は「位置だけ」です。盤面ARマーカーを各フレームで2個以上参照し、前後の色目印の中点を盤面左上原点のX右向き・Y下向き、mmで記録します。動画の軌跡を選ぶと`position_trajectory.png`を表示します。位置解析には走行CSV・時刻合わせを使いません。出力は高さ未補正の見かけの中点で、車軸の絶対位置や停止合否を示しません。欠測は`position.csv`の`position_valid=False`とNaNで残します。「ログと比較」では従来の入口方向を基準とする相対比較を行います。

ARマーカーが映っていても、カメラ移動で保存済み参照の`marker_search_rois_px`から外れると盤面登録に失敗します。「位置だけ」では解析前に動画の冒頭を検査し、3枚以上を登録した基準で全登録IDを重複なく実復号でき、既存の盤面・格子品質条件も通った場合に検索範囲だけを自動調整します。実際の座標変換は各フレームで改めてARマーカー2個以上から求めます。調整結果は試行内の`quick/marker_reference_used.json`・`full/marker_reference_used.json`へ保存し、元の基準・取得済み資料は変更しません。

「位置＋外観学習（試験）」は、色目印が読めないフレームだけ機体の外観モデルと任意の小型CNNを使う入口です。初期設定は従来の「位置だけ」のままです。使用には機体・前後色が一致するモデル一覧`tools/pixel_camera_detector_models.json`、または`tools/logs/pixel_camera/detector_models/registry.json`が必要です。モデルが未登録・改変・別機体の場合は設定送信・走行前に停止します。実験モデルの学習・独立動画での検証・登録形式は[解析手順](analysis/README.md#機体外観学習と小型cnnの試験)を参照してください。

学習から補った位置は軌跡図の橙点と`position_estimated=True`で示し、実観測の`position_valid`・観測率へ含めません。CSVの`estimated_center_x_mm`・`estimated_center_y_mm`へ分けて保存します。`summary.json`には推定件数、観測＋推定の被覆率、終点が観測か推定かを残します。補ったフレームでもその時点の盤面AR登録が必須です。モデルは試行内の`detector_models/`へコピーしハッシュを保存するため、後の再学習で過去の結果を変えません。推定を含む位置からターン値を自動採用しません。

自動調整も不成立なら、4隅のARマーカー全体を画角へ入れ、同じIDの別マーカー・反射・格子の遮蔽を確認してください。`summary.json`の`reference_search`に元の失敗理由と調整の成否を残します。機体の色目印の失敗とは別です。GUIの詳細欄にも解析の失敗理由を表示します。必要なら現在の映像で読み取り範囲を手動設定し、別名の参照JSONを「接続・撮影条件」から選びます。

映像解析を選んでいて目印設定・解析環境が不足する場合は②の段階で案内し、走行へ進みません。「録画のみ」または録画OFFなら映像解析設定は不要で、取得後のログ画像までを自動で保存します。

本体保存ログは400件のリングです。1 msなら約0.4秒、5 msなら約2秒を保持し、Lendまでの最新データを残します。ターン後の減速・制動区間は含みません。長いターンでは周期を広げてください。別途取得する5 msのBLE連続CSVは前走・後走と停止まで残します。

保存先は`tools/logs/pixel_camera/tuning_gui_日時_ID/run_時刻_ID/`です。

| ファイル | 内容 |
| --- | --- |
| `saved_<周期>ms.csv` | 本体保存ログ。`cnt`は最古の保存サンプルからの経過ms。絶対MCU時刻ではありません |
| `saved_<周期>ms.settings.json` | 読み返した実機設定・記録周期・件数・列名 |
| `log.png` / `log_preview.png` | 目標・実測の速度、角速度、角度、軌跡、出力、FF等の比較画像／GUI縮小版 |
| `requested.settings.json` | 画面の要求値 |
| `telemetry.csv` / `motion.csv` | 5 msのBLE連続CSV／今回の走行区間 |
| `trial.json` / `events.jsonl` | 機体、録画ON/OFF、周期、停止確認、実行・取得の結果と時刻 |
| `workflow_result.json` | 設定送信時の記録との対応、ログ画像・自動解析の結果、次試行の手動開始条件 |
| `quick/` / `full/` | 映像解析ONで作成する速報／全フレームの軌跡・位置比較・解析JSON |
| `analysis_plan.json` | 今回選んだ方式。録画のみは`record_only`、AR正対補正のみは`rectify_only` |

設定だけの送信はセッション内の`settings_時刻_ID/`へ要求値、読返し値、通信履歴を保存します。試行結果の`workflow_result.json`から対応を参照できます。次の試行は新しいフォルダーへ保存し、前のCSV・動画・画像を保持します。

画像だけの再作成は`python tools/turn_tuning_log.py <trial.json>`です。周期とCSVの時刻を照合し、その周期で角加速度・軌跡も計算します。欠測や周期不一致は成功扱いにしません。

録画ONでは従来の[Pixel撮影手順](pixel_camera_README.md#調整guiで撮影と単体走行をまとめる)のPCサーバー・PyAVが必要です。ログ画像には従来どおりNumPy・pandas・Matplotlibを使います。映像解析を選んだ場合は追加の解析環境も必要です。カメラ用Pythonからも同じ`tools/turn_tuning.py`を起動できます。調整用の撮影設定と、位置を評価する各フレームで登録済みArUcoを2個以上参照する条件を維持します。「動画の軌跡」へ切り替えると選んだ方式の全フレーム解析画像、未作成なら速報画像を表示します。「録画のみ」では軌跡画像を作りません。

このPCで復元したカメラ環境は`.tools/pixel_camera_runtime/environment.json`から再利用し、依存パッケージはPythonの版に対応する`.tools/camera_python312/`等から読みます。接続サーバーは同じruntimeを共用します。別PCでは`PIXEL_CAMERA_REPO`へカメラコードを指定し、必要な依存環境を用意してください。起動・環境読込みだけでは接続・撮影・走行しません。

編集値は単体調整用の実機RAM値です。再起動・preset/resetで戻り、連続turnpatternや最短走行の機体別設定へ自動採用されません。

機体別の接続先は次のとおりです。交換したHY0020などのアドレスは「接続・撮影条件」タブで編集でき、機体ごとに保存されます。

| 機体 | BLE広告名 | BLEアドレス |
| --- | --- | --- |
| A | `HY0020-MOUSE-A` | `C1:B5:60:87:91:73` |
| B | `HY0020-MOUSE-B` | `E1:7F:86:21:84:73` |

別機体の既知アドレスは接続前に拒否します。接続中の機体変更も拒否します。機体を変える際はDisconnectしてから選び直し、`Load defaults`で対象機体の値を取得してください。別機体の調整値を引き継がないよう、切替時に入力欄と設置確認をクリアします。

接続失敗時は、選択した広告名・アドレスと中継のエラー原文を画面に表示します。詳細は保存先の`gateway.stderr.txt`です。

カメラ接続時の`CONNECTION_FAILED`・`WinError 10061`は、PC側のカメラサーバー（8765番）が起動していない等で接続を拒否された状態です。BLE中継（8766番）とは別です。カメラサーバーを起動し、スマホの「PC接続を開始」で接続済み・待機中に戻してから②をやり直してください。「実行は再送しません」は二重走行を避けるための表示で、自動の再実行は行いません。
