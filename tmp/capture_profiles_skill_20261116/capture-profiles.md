# 調整盤と9×9迷路の録画設定を切り替える

調整用・9×9迷路用の録画、GUI起動、画角の変更時に読む。ユーザーは両用途の設定分離と、ArUcoの必須参照を指定している。

## 用途と既存GUIを選ぶ

| 用途 | 起動するGUI | 撮影プロファイル |
| --- | --- | --- |
| 壁なし調整盤で単体ターンを撮影 | `tools/Start_Pixel_Tuning.cmd` / `tools/pixel_camera_tuning.py` | `tuning` |
| 9×9迷路の探索・最短走行を録画 | `tools/Start_BLE_Explore_Camera.cmd` / `tools/ble/mouse_ble_explore_camera_gui.py` | `maze_9x9` |

Pixel接続は既存のカメラGUIを使う。録画付きの両GUIはカメラ8765・BLE8766を使う。素のBLE中継の既定8765と同時に使わず、接続中の別クライアントを閉じて切り替える。GUIを開くだけでは接続・設定送信・録画・走行を始めない。

詳しい操作は[Pixel撮影手順](../../../../tools/pixel_camera_README.md)と[BLE録画付き探索手順](../../../../tools/ble/README.md)を確認する。

## 撮影条件を用途別に復元する

- 保存先は `tools/logs/pixel_camera/capture_profiles/tuning.json` と `maze_9x9.json`。EV、ズーム倍率、ライト、AF固定の4項目を分離する。EVが同じでも一つの共有設定へ戻さない。
- 調整GUIは「撮影条件」、9×9 GUIは撮影EV・ライト・ズーム倍率・AF固定の欄を確認する。撮影開始時に選んだ用途の値を保存し、**毎回の録画直前に全項目を適用・受付照合する**。直前に使った端末設定が残っていることを前提にしない。受付不一致なら録画・走行へ進まない。
- 共通実装は [pixel_camera_profiles.py](../../../../tools/pixel_camera_profiles.py)。`load_camera_profile` / `save_camera_profile` / `configure_camera` を使う。調整CLI・単独撮影も `tuning` を使う。EVから端末ステップへの変換は実機の刻みで行う。
- 保存済み値を優先する。未保存時の既定値は調整用−2.5 EV、9×9用−2 EVで、両方とも1倍・ライトOFF・AF固定ON。旧 `explore_capture_preferences.json` は9×9の初期値移行用として読み、測定根拠を上書きしない。
- カメラ高さ、盤面参照、機体A/Bの色・高さなどは4項目の撮影プロファイルとは別。調整用の `tuning_ui.json` や今回の設定JSONも照合する。ズーム倍率を変えても、解析に渡す実際のカメラ高さを書き換えて帳尻を合わせない。

### 2026-11-16に確認した再開用の値

| 項目 | 壁なし調整盤・機体A | 9×9迷路 |
| --- | --- | --- |
| EV / ズーム | −2 EV / 2倍 | −2 EV / 1倍 |
| ライト / AF固定 | OFF / ON | OFF / ON |
| カメラ高さ | ユーザー確認1500 mm。古い800 mmを復元しない | 今回の配置で確認。調整盤の1500 mmを無条件に流用しない |
| 盤面 | 今回は360 mm・45 mm格子の調整盤 | 9×9・1セル90 mm（全幅810 mm相当） |

これは同じ機材・照明・配置を再開する際の記録で、全環境の固定値ではない。現在の保存値とユーザー指定を優先し、配置変更後は画角・参照・検出を再確認する。

調整用の高さ・参照・機体JSONの根拠は [turn1600準備記録](../../../../tools/logs/pixel_camera/turn1600_A_r90_20261116_preflight_v1/preparation.json)。9×9の基準は [board_9x9_reference.json](../../../../tools/logs/pixel_camera/board_9x9_reference.json)。ログ領域が移動・未復元の場合は実際の保存先を探し、パスだけで基準を推測しない。

## ArUcoを毎評価フレームで必ず参照する

- 調整盤と9×9の登録基準JSONを混用しない。盤面寸法・原点・軸・登録ID・元画像を確認する。機体の前後色やマーカー高さも機体別の設定を使う。
- **位置・軌跡を評価する各フレームで、登録済みArUcoを2個以上実復号した頂点から盤面登録を求める。** 格子補正のON/OFFにかかわらず必須。色の前後マーカーだけが読めても登録の代用にしない。
- 2個未満、重複ID、退化、残差過大のフレームは欠測として位置評価から除外する。前フレームの変換、全フレームの中央値、別動画、未読IDの推測で補完しない。登録の有効マスクと観測率を保存する。
- 古い解析キャッシュに毎フレームの登録証拠・有効マスクがなければ使わず、元動画から別の出力先へ解析する。元データを保持する。
- 画角変更後は、盤面・動作範囲と2個以上の登録済みArUcoが映ることを静止撮影で確認する。`marker_search_rois_px` がある基準は現在の画像範囲と照合する。同じIDの別盤を拾わない。走行後も動作全区間の欠測・誤認を検査し、静止確認だけで走行中の品質を保証しない。
- 9×9 GUIは「前後マーカーを自動追跡」を選び、9×9基準と1セル90 mmを指定する。調整GUIは「撮影条件」の参照・機体JSONと今回のカメラ高さを確認する。選んだ基準と設定を試行内へスナップショット保存し、動画・CSV・実機設定へ結び付ける。

ArUco参照が成立しても、未知のカメラ高さ・真下位置・レンズ歪みまで校正済みにはならない。入口方向に合わせた相対軌跡、盤面固定の位置、車軸の絶対位置を区別する。撮影条件の受付一致も、明るさ・合焦・物理240 fpsの実測確認とは別。
