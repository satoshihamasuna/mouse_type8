# 実装状況と次の検証

## 実装済み

- Phase 1: Camera2/MediaCodec機能調査、720p240の試験録画、タイムスタンプ・フレーム数・SHA-256・CSV。
- Phase 2: 可視Activityから起動するcamera型RecordingService、録画状態、手動停止、自動停止。現時点の録画長は1〜30秒。
- Phase 3: ADB reverseのUSB接続、認証付きWebSocketコマンド、HTTPによるMP4・JSON・CSV転送、照合後の元動画削除。
- Phase 4: 共通PixelCameraClient API、複数クライアントの操作権、重複開始の防止、タイムアウト、状態監視。
- Phase 5: PySide6 GUI、保存先、開始・停止、自動停止秒数、経過時間、残量、転送進捗・速度、履歴、エラー表示。

[使い方](USB_REMOTE.md)と[USB実機試験](USB_TEST_20261108.md)を参照。

## 継続して必要なカメラ検証

接続端末はPixel 4a (5G) / Android 14。4Gモデルでの動作は未確認。
動画のPTS・件数・実時間は約240 fpsと整合し、デコードも確認できた。センサー通知は8フレームごとのため、約4.17 msの物理的な時間分解能は独立した時間基準の撮影で確認する必要がある。
通常カメラの設定範囲を、高速撮影で利用できるものと扱わない。EV等の実効性を測定してから設定APIとGUIを拡張する。

## 開発対象

接続方式はUSBに限定する。ユーザーの方針により、Wi-Fiは今回の開発対象から外した。

## 録画時間と連続試験

最初の映像PTSを録画時間の起点とし、カメラ準備時間による動画の短縮を修正した。指定時間以後の末尾フレームだけを除外し、その数を記録する。PTSの間隔は変更しない。
GUIとCLIに反復回数の指定、PCでの全フレーム復号、サイズ・SHA-256再照合、端末削除通知の確認、HTML/JSON/CSVレポートを追加した。詳細は[連続撮影試験](USB_REMOTE.md#連続撮影試験)を参照。転送・削除直後の残量と未転送数も更新する。

## Phase 7: 安定性と長時間録画

- 10秒×20回と30秒×20回は実機で全回合格。全フレーム復号・サイズ/SHA-256再照合・端末削除通知を確認。測定結果はUSB_TEST_20261108.mdを参照。
- コマ送り検査、PTS表示、24コマの一覧画像と元動画ハッシュの保存を追加。外部の時間基準を用意して物理240 fpsを検証する。
- より長時間の熱状態と、ストレージ容量不足を実機で測定する。
- 物理USB抜き差し、転送途中の通信断、ACK消失、Androidプロセス強制終了、PC電源断の復旧を追加検証する。
- 30秒を超える録画、MP4の分割、タイムスタンプの継続性を設計する。
- 必要に応じてチャンク再開を追加する。現状の再転送は先頭から行う。
- プレビューは240 fpsの安定性を比較測定した後に追加する。

照合成功より前に端末動画を削除しないこと、再送でPC動画を重複させないこと、測定根拠をメタデータに残すことを維持する。
